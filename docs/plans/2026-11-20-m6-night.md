**Goal.** Close the loop while the operator sleeps and commutes, without a new money model: a **Spending Mandate** is the operator's own
two-factor act in the app that lets the night shift spend inside a scope (modes, engines, minimum stars, per-lineage limits, a per-batch
ceiling, a budget and an expiry), consumed against settled plus reserved spend, revocable from the phone and never raising a cap; the
**Night Shift** plans a small explore/exploit batch at the configured time, one take per lineage, trims it to the mandate's per-night
ceiling (compared with the estimate's **ceiling**), creates it through the ordinary M3 estimate and create path and can be halted from the
phone; the **Morning Crate** turns last night's and other unjudged takes into a blind, loudness-matched, lossless commute tape every day
at 07:00 local time (40 minutes), judged with earbud buttons and on-screen blind stars, available offline in the PWA and exposed as a
native Subsonic playlist only at reveal; the **Critic Bench** measures how well every agent critic and every Tier A and Tier B signal
agrees with the operator's own ratings and blind duels, including the label critic `diction.line_cer` for the Diction Lab.

**Architecture (one paragraph).** Four new packages (G1 C320.1 names): `internal/mandates` (the authority), `internal/nightshift` (the
planner and the nightly runner), `internal/morning` (selection, side builder, events, reveal) and `internal/criticbench` (pure
agreement maths over SQL reads). The night shift acts as one fixed server-side agent principal, `agent:nightshift`, which owns no token:
its only authority to spend without a human click is a live mandate held by it. It prices candidate nights with a new read-only
`generation.(*Service).Preview` (an estimate that writes nothing), then makes exactly one `Estimate` and one `Create` in process with
`EstimateIn.MandateID` set; generation asks the injected `MandateCover` whether the mandate covers the plan (strict: no estimate row on
refusal), re-checks it inside the create transaction, and writes an `auto` approval with `via = 'mandate'`. Caps are checked exactly as
today, before the mandate. Both daily jobs run through G1's `internal/schedule.Daily` in the configured zone (`MM_TZ`) as
`app.Services.Loops`. The Morning Crate stores raw headset and rating events and maps them to comments, ratings and listen events only
in the reveal transaction, so nothing identifies a chapter before the reveal. The Critic Bench never writes; its trust states are used
only as labels and as the night planner's last tie-breaker.

  program items are G1's and the other tracks'). MCP widgets and the upgrade gate are out; none of the four needs them.
- **D-M6N-OP-2 ACE-Step rejected.** Nothing here depends on ACE-Step: a mandate's engines must be adopted engines (`acestep15` is

- **D-M6N-OP-3 Night-shift money.** A per-night ceiling (value in the private appendix) is compared with the estimate **ceiling**
  (`ceiling_micro_usd`), not the expected spend; the operator understands that real spend is a fraction of it. The monthly cap and every
  other cap stay as they are; nothing raises a cap; the mandate is the operator's own two-factor act in the app.
- **D-M6N-OP-4 Morning Crate.** Built daily at 07:00 local time (`MM_TZ`, value in the private appendix), 40 minutes, **blind**: titles
  hidden until the operator has rated; the native Subsonic playlist appears only at reveal.
- **D-M6N-OP-5 Listening checks (Tier B).** On new takes only; every new render opts in by default and its cost is in the estimate, so a
  night's takes carry Tier B when the Ears capability is open. The library is not analysed automatically (nothing here does).
- **D-M6N-OP-6 Builders.** Sonnet agents lane by lane (TDD, one worktree per lane, one PR per lane, CI is the heavy gate); lanes are
  sized for that.

**Plan decisions:**

- **D-M6N-1 Mandate = authority, settings = behaviour.** Everything that bounds money lives in the mandate (budget, expiry, per-batch
  ceiling, batches per local day, takes per batch, takes per lineage, modes, engines, minimum stars, lineage filter, Tier B allowed). The
  night-shift settings hold only behaviour (time, enabled, explore ratio, planner star threshold, listening checks on or off) and no money.
- **D-M6N-2 Operator-created mandates only.** `create_mandate` is `HumanOnly` + `OwnerOnly` + `cost: approve` under `/human/api/`
  (edge two-factor rule; in-app step-up when configured). A mandate is born `approved`; the only transition is `approved → revoked`.
  No agent proposes, no rehearsal (YAGNI: `preview_night_shift` shows tonight's plan and price). At most one non-ended, non-revoked
  mandate per holder (409 `MANDATE_ACTIVE`).
- **D-M6N-3 The night principal.** `agent:nightshift` (`Kind agent`, `ID "nightshift"`, `Via "nightshift"`, scopes `read`,
  `generate`), defined in `internal/nightshift`, never stored in `api_tokens` (token ids are UUIDv7, `internal/auth/tokens.go:102`, so
  no collision). Agent kind because `estimates.principal_kind` and `batches.principal_kind` allow only `human|agent`
  (`0007_generate.sql:71`, `:110`) and because every agent rule applies to it (global agent daily cap, callbacks backlog gate, auto
  limits irrelevant under a mandate). It never approves anything: without a covering mandate its night is skipped, never queued for
  approval.
- **D-M6N-4 Strict, Go-only mandate field.** `generation.EstimateIn.MandateID` is not part of the REST or MCP input; only the night
  runner sets it. With it set, a non-covering plan is a 409 `MANDATE_UNAVAILABLE` with reasons and writes no estimate row and no token.
  Without it, generation is byte-identical to today. A mandate is never chosen automatically.
- **D-M6N-5 The per-night ceiling is a mandate field** (`max_batch_ceiling_micro_usd`, ≤ the global batch cap at creation) plus
  `max_batches_per_day` (local days, `MM_TZ`; 1 for the night shift). Raising the night ceiling therefore needs a new mandate.
- **D-M6N-6 No night queue in v1.** The planner is explore/exploit only; the operator focuses nights with the mandate's
  `root_track_ids`. Re-entry: the operator asks for it.
- **D-M6N-7 One take per lineage per night**, `n_seeds = 1`, at most `min(settings.max_takes, scope.max_takes_per_batch)` takes, then
  trimmed from the end until the estimate's ceiling fits the mandate.
- **D-M6N-8 Who may see and run what (U1).** Mandates, night shift, Morning Crate and Critic Bench are **Owner-only** for people
  (`OwnerOnly` on every op): Editors never see money and never authorise spend (D-U1-11, D-U1-12); crate verdicts, blind ratings and
  critic trust are Owner curation signals (D-U1-9, D-U1-10, G1 D-G1-16). **Listeners do not get the crate** in v1: it writes the
  Owner's ratings, is built from unreleased nightly takes, and a per-user crate would need per-user blind state and rater-keyed mapping
  (open question 1). Agents (Owner delegates) may read everything and may halt, revoke and build, because those only reduce spend or are
  free; agents may not create mandates, change night settings, submit crate events or reveal (human-only or person-only). After reveal
  the takes are ordinary library takes under U1's existing rules, and the reveal playlist is an ordinary shared playlist.
- **D-M6N-9 No notifications.** No ntfy message is sent by anything in this plan (the operator wants none); the crate-ready state is a
  card on the New page and a badge; a failed night shows on `/night-shift`.
- **D-M6N-10 Crate sides** are one derived 24-bit/48 kHz stereo FLAC each (YuE2 masters are 48 kHz, `internal/engine/yue2/engine.go:19`),
  at most 15 minutes and 200 MiB, sample-exact chapter maps, `CHAPTERnnn` Vorbis comments, no CUESHEET (draft D-M6-7 kept); gain per take
  `min(−16 − I, −1 − TP)` dB with an explicit power-preserving mono upmix (draft D-M6-8 kept); sides live under `derived/morning/`,
  mode 0444, are not backed up (`internal/backup/snapshot.go:336-343` lists the backed-up path columns) and are swept after `keep_days`.
- **D-M6N-11 Crate events are raw and mapped at reveal** (draft D-M6-10 kept): before reveal no comment, rating or listen event touches a
  real take; mapping runs in the reveal transaction and, after reveal, in each event's insert transaction.
- **D-M6N-12 Reveal.** Automatic when every non-anchor chapter has blind stars from an Owner-side person; manual at any time by the Owner
  (a person, not an agent). The Subsonic-visible playlist "Morning crate YYYY-MM-DD" is created in the reveal transaction, never before.
- **D-M6N-13 Catch-up** (answers G1 open question 2): the Morning Crate builds late within **2 h** of 07:00 after a restart, then skips
  the day; the night shift catches up within 2 h of its time. Both use `schedule.Daily.Done` = "a row exists for this local-day key".
- **D-M6N-14 Critic Bench references.** Primary: the **Owner's** ratings (`owner_ratings`), pairs of takes in the **same lineage** with
  different stars; secondary: the Owner's blind duel verdicts; for label critics: the Owner's Diction Lab line marks. Effective sample
  size is `min(pairs, distinct takes)` so shared takes never inflate confidence. Trust rule (draft D-M6-16 kept): `trusted` iff
  `n_eff ≥ 30 ∧ lo > 0.55`, `contrary` iff `n_eff ≥ 30 ∧ hi < 0.45`, `insufficient` iff `n_eff < 30`, else `unknown`. Nothing acts on
  trust except labels and the night planner's last tie-breaker.
- **D-M6N-15 MCP.** 16 new operations, none first-class: 12 `generic`, 2 `exclude:human-only` (`create_mandate`, `update_night_shift`),
  2 `exclude:person-only` (`submit_morning_crate_events`, `reveal_morning_crate`, the `create_voice_note` precedent). The existing tool
  schemas grow only by the approval `via` doc text (≤ 50 bytes of G1's 4 000-byte budget).
- **D-M6N-16 No new environment variable.** Every setting is in the database and edited through operations; `MM_TZ` is G1's.

### C367. Mandate accounting (`internal/spend/mandate.go`; spend owns the money maths)

```go

    Settled, Reserved, Used, Committed, Excess money.MicroUSD // Used = Settled + Reserved
    Batches, Takes int
    ByRoot     map[string]int // takes per lineage root of the job's parent, over non-rejected, non-expired batches

```

operator called "settled + reserved"), `Committed = Σ contribution ≥ Used`. `excess` is shown, never counted (it is provider overshoot
above the execution pot and already trips the provider; M3's per-pot invariant excludes it the same way). `TestMandateUsage_Table`
(budget 1 000 000; an active batch with ceiling 943 587 ⇒ committed 943 587, used = its reserves; a new ceiling 56 413 fits, 56 414 does

an active batch changes neither `Used` nor `Committed` and appears in `Excess`; three takes on two roots ⇒ `ByRoot` {r1: 2, r2: 1}),

### C373. The planner (`internal/nightshift/plan.go`, pure; `read.go` builds its input)

1. **Input.**
   ```go
   type Lineage struct {
       RootID, BestTrackID, Engine, Style string
       BestStars      *int     // the Owner's stars of the best take (owner_ratings)
       U, SD          *float64 // ladder strength of the best take; nil without counted duels
       NDuels         int
       RecentUnjudged bool // a night-shift take of this root from the last 3 nights has no Owner rating
       Backlogged     bool // the callbacks backlog gate would refuse an agent item on this root (generation.BacklogGate)
   }
   type Input struct {
       Lineages []Lineage; Scope mandates.Scope; ByRoot map[string]int
       MaxTakes, MinStars int; ExplorePPM int64; TierB bool; Seed uint64 // seed = fnv64a(night key)
       TieBreak map[string]float64 // root ⇒ Σ standardized values of trusted critics (C387.4); nil when absent
   }
   type Planned struct{ Kind string /* exploit|explore */; RootID string; Item generation.Item; Reason string }
   type Dropped struct{ RootID, Reason string }
   func Plan(in Input) (planned []Planned, dropped []Dropped)
   ```
   **Best take of a lineage** (`read.go`): among the root's takes that are not discarded, whose recipe engine is in `Scope.Engines` and
   whose recipe is a render: the highest `U` with `NDuels ≥ 3`, else the highest Owner stars, else none (unrated lineages are not
   candidates). Only `owner_ratings` is read (D-U1-9). `TestReadLineages_BestTakeRule`, `TestReadLineages_OwnerRatingsOnly`.
2. **Scope filter** (every candidate): mode ∈ `Scope.Modes`, engine ∈ `Scope.Engines`, `BestStars ≥ Scope.MinStars`, root ∈
   `Scope.RootTrackIDs` when set, `ByRoot[root] + 1 ≤ Scope.MaxTakesPerLineage`, not `Backlogged`, not `RecentUnjudged`. Failures go to
   `dropped` with that reason.
3. **Split.** `N = min(MaxTakes, Scope.MaxTakesPerBatch)`; `explore = (N × ExplorePPM + 500 000) / 1 000 000`; `exploit = N − explore`.
   Exploit pool: candidates with `BestStars ≥ MinStars` ranked by `U` desc (only `NDuels ≥ 3`), then stars desc, then `TieBreak` desc,
   then `fnv64a(seed, root)`; item `{mode: new_seed, parent_track_id: best, n_seeds: 1}`. Explore pool: the remaining candidates with
   `BestStars ≥ max(Scope.MinStars, MinStars − 1)` or `SD ≥ 1.0` (nil `SD` counts as the prior 1.5), ranked by `SD` desc (nil first), then
   `TieBreak`, then the seeded hash; item: when `yue2.StyleTerms(style)` has a BPM term, `{mode: style_edit, parent_track_id: best,

### C374. Pricing a night: the per-night ceiling and how many takes it admits

1. **Rule.** The runner compares the estimate's **ceiling** (`ceiling_micro_usd`) with the mandate's `max_batch_ceiling_micro_usd`
   (D-M6N-OP-3, G1 C327.4) and trims the planned list from the end until `Preview` reports it covered; the expected spend is shown but
   never used for the decision. The number of takes is therefore whatever the live quote admits that night; the table below is for
   orientation and for choosing `max_takes`.
2. **Formula, from the code.** Per take (`spend.QuoteTakes`, `internal/spend/quote.go:106-147`): `gen = 10 + ⌈rtf × audio / 1000⌉`;
   `timeout = min(MaxRuntimeS, ⌈1.6 × gen⌉ + 80)`; `take = ForSeconds(timeout + KillSlackS, price)`; `max = take + ForSeconds(ColdStartS +
   IdleS, price)`; batch `ceiling = (n + min(n, WorkersMax)) × max` for equal takes; `expected = n × ForSeconds(gen + 10, price) +
   ForSeconds(ColdStartS + IdleS, price)`. `price` = list × 1.1 (`estimate.go:46`), `rtf` ≥ 680 while an allowed GPU class is unmeasured
   (`quote.go:248-260`). **Tier B** (the Ears term, `TakeIn.EarsS`, Ears C339.1–C339.2, defaults 40 / 200 / 40 from its
   `config_ears.go`): `ears_s = 40 + ⌈200 × audio / 1000⌉` (+ `⌈40 × audio / 1000⌉` when the score is transcribed), `timeout = /1 timeout
   + ⌈1.5 × ears_s⌉`, `expected_s += ears_s`; the render window is unchanged (G1 D-G1-19).
3. **Worked example at the golden parameters** (`quote_test.go:13`: 690 000 µUSD/h, rtf 680, cold start 180 s, idle 20 s, `workers.max`

### C378. Morning Crate pure core (`internal/morning/plan.go`, `gain.go`, `slate.go`; stdlib only)

The draft C118.1 types are kept with these names and defaults: `Options{Minutes 40, SideMinutes 15, MaxTakes 14, Anchors 1, SlateMS 1500,
MaxSideBytes 200 MiB, IncludeTruncated false}`; `Candidate{TrackID, RootID, MasterSHA, MasterPath, DurationS, TotalSamples, SampleRate,
Channels, Source ("manual"|"night_shift"|"job"), CreatedAt, LUFS, TruePeak, Truncated}`; `Chapter{N, TrackID, Anchor, Start, AudioStart,
End, GainCDB, Limited}`; `Side{Index, Chapters, Samples}`; `Plan{Seed, Sides, Excluded, AdjacencyRelaxed}`; `Select`, `Gain`, `SlateFreq`,
`SlatePCM`, `ChapterAt`.
1. **Selection.** Anchors first (up to `Anchors`, from the anchor pool: Owner ★5 else status `final`, distinct roots, roots absent from
   the candidates preferred, seeded), their time reserved; then candidates in source order `manual` → `night_shift` (newest first) →

   `truncated`, `no_loudness`, `channels` (> 2).
2. **Blind order.** Shuffle with `math/rand/v2.NewPCG(seed, 0)`; an anchor never first; no two adjacent chapters of one root when avoidable,
   else `AdjacencyRelaxed`.
3. **Sides.** Fill in order while `Σ ≤ SideMinutes × 60` and the byte estimate `samples × 6 × 0.62 ≤ MaxSideBytes` (the ratio is measured
   in `loop-morning-build` and recorded).
4. **Gain and slates** as draft D-M6-8 and C118.1: `g = min(−16 − LUFS, −1 − TP)`, `cdb = round_half_away(g × 100)`, `limited` iff the
   true-peak term binds; slate `n`: 1.0 s sine at `440 × 2^(((n−1) mod 12)/12)` Hz, −20 dBFS, 20 ms raised-cosine fades, then 0.5 s of zero.
5. Tests: `TestSelect_FitsMinutes` (10 candidates × 240 s, distinct roots, `Anchors 0` ⇒ 9 chapters, 2 173.5 s, sides [3, 3, 3];
   `Anchors 1` with a 240 s anchor ⇒ 1 + 8 chapters, sides [3, 3, 3]), `TestSelect_AnchorsReservedFirst`, `TestSelect_SiblingsApart` (8
   candidates of 3 roots, 4/2/2 ⇒ no adjacent equal roots for seeds 1…100), `TestSelect_AnchorNeverFirst`, `TestSelect_AdjacencyRelaxed`,

6. **As built (M6N-C1, amended contract).** The draft C118.1 is not in the repo, so the shapes are fixed here:
   `Select(in Input, opts Options, seed uint64) Plan` with `Input{Candidates, Anchors5, AnchorsFinal []Candidate}` (the five-star pool fills
   the anchor slots first, the final-status pool only what is left); anchors count towards `MaxTakes`; `DefaultOptions()` holds the C378
   defaults. Positions in `Chapter` and `Side.Samples` are frames at 48 kHz relative to the side (`Start` = slate start, `AudioStart` =
   `Start + SlateMS*48`, `End` = end of audio); `Side.Index` is 0-based, `Chapter.N` is 1-based and global, and is the slate number. A
   candidate's frames are `TotalSamples` rescaled to 48 kHz (`DurationS` when `TotalSamples` is 0). `no_loudness` means NaN/Inf or `LUFS`
   and `TruePeak` both exactly 0. A take that alone exceeds a side (minutes or byte estimate) is `over_budget`; a take with no audio
   frames is a fifth exclusion, `no_audio`. Candidates that do not fit are `over_budget` and scanning continues, so a shorter one may
   still enter. Exclusions are listed in visit order (source, newest first, track id). `Gain` snaps to micro-dB before rounding so binary
   noise cannot flip a half-centi-dB tie. `SlatePCM(n)` is 24-bit little-endian stereo, `SlateSamples*6` bytes. `ChapterAt(side, frame)`
   works on frames (the caller converts events' ms); the slate counts as part of its chapter. Blind order is seeded randomised greedy (400
   tries, first without an adjacent root wins, else the fewest) so `AdjacencyRelaxed` is true only when it cannot be avoided.

### C385. Critic Bench references and maths (`internal/criticbench/{pairs.go,wilson.go}`, pure)

```go
type Pair struct{ A, B, Winner string; Root string; At time.Time } // ratings: Winner = the higher Owner stars; duels: the verdict's winner
type Score struct {
    Pairs, NEff, Agree, Predicted int; Rate, Lo, Hi float64 // Wilson 95 % (z 1.96) on (round(Rate × NEff), NEff)
    State string          // insufficient | unknown | trusted | contrary (D-M6N-14)
    Coverage float64       // pairs where the critic has both values / pairs in the window
    Disagreements []string // newest ≤ 10 pair keys or duel ids (only when one critic is requested)
}
func Wilson(k, n int) (lo, hi float64)
func RatingPairs(owner map[string]int, roots map[string]string, at map[string]time.Time, window int) []Pair // window 400
func Metric(direction int, minDelta float64, v map[string]float64, pairs []Pair) Score
func Pairwise(pairs []Pair, verdicts map[string]string) Score
func SlotBias(aCount, abCount int) (share, lo, hi float64, biased bool) // biased iff abCount ≥ 20 and 0.5 ∉ [lo, hi]
func Labels(pred, human map[string]bool) Score // keyed by line; the caller builds both maps
```
1. **Reference `ratings`** (primary): every unordered pair of takes with the **same lineage root**, both rated by the Owner
   (`owner_ratings`), with different stars; newest 400 pairs by the later rating's `updated_at`. **Reference `duels`**: the Owner's verdicts
   `a|b` on duels with `blind = 1` and `saw_reveal = 0`, newest 200. **Reference `lines`**: the Owner's Diction Lab line marks (C386.4).
   `NEff = min(Pairs, distinct takes in the pairs)` (lines: the number of marked lines).
2. A metric critic predicts `A` over `B` when `direction × (m_A − m_B) ≥ minDelta`; no prediction otherwise (`Predicted` counts them;
   `Rate = Agree / Predicted`).

## Rollout and risks

1. **An unattended spender.** The night shift spends without a click. Mitigations: authority only from the operator's two-factor mandate;
   per-night ceiling compared with the estimate ceiling; caps checked first and never raised; one batch per night by schema; halt and
   revoke from the phone; the property test; the first night attended (X3).
2. **The spend path edit.** `loop-spendpath` edits `generation` estimate and create, the most sensitive code. Mitigations: the change is
   inert without `MandateID` (byte-identical tests), merges after G1-F3b alone, Preview is a split of the existing body with an equality
   test.
3. **Mandate accounting drift.** Mitigation: `Used ≤ Committed ≤ budget` at every ledger commit (property), `excess` reported apart.
4. **A night that never runs** (restart, DST, disabled capability, closed Tier B cap). Mitigations: catch-up 2 h, `01:30` outside the DST
   hours, `skipped` reasons on `/night-shift`, Tier B fallback.
5. **Blindness leaks** (a playlist, comment, rating, cover or title before reveal). Mitigations: raw events, mapping only at reveal,
   `TestMorning_BlindRedaction`, `TestMorningEvents_NoJudgmentRowsBeforeReveal`, app-icon artwork, no notification bodies.
6. **Disk and phone storage.** A 40-minute 24-bit side set is a few hundred MB per day on the server and on the phone. Mitigations:
   `keep_days` 7, shared sides, the phone keeps only the newest crate offline; the size is measured in `loop-morning-build`.
7. **iOS media quirks** (auto-advance, lock-screen buttons). Mitigation: one media item per side, synchronous side change, device
   checklist.
8. **Critic over-trust.** Mitigations: within-lineage pairs, `NEff`, Wilson bounds, trust only labels and tie-breaks.
9. **Shared-file churn** (generation, judgments, listening, playlists, player, nav, audit). Mitigations: additive `*_m6n.go` files, one
   web lane at a time, `make regen` after every rebase, amendments A1–A3.
