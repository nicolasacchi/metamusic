# metamusic Roadmap (M0 → M6, with L1–L3, E2 and T1)

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or subagent-driven-development)
> to implement each milestone from its own detailed plan `docs/plans/<date>-m<N>-*.md`, written just
> before the milestone starts. This file is the stable index; detailed plans refine it.

**Goal:** a personal YuE2 music lab where the generate → listen → judge → regenerate loop is equally
drivable from a phone/web UI and from an LLM agent, with lossless mobile listening and hard money safety.

**Architecture:** one Go 1.27 binary (Huma v2 REST/OpenAPI 3.1 = the operation registry; MCP tools
derived from it; OpenSubsonic adapter; job runner; SQLite WAL) embedding a Svelte 5 SPA/PWA.
GPU renders run on a RunPod Serverless endpoint using a worker image built by CI. Deployed behind
a reverse proxy with forward-auth SSO for humans; agents use scoped tokens / OAuth.

**Tech stack:** Go 1.27, Huma v2, modelcontextprotocol/go-sdk, modernc.org/sqlite, ffmpeg + flac
(runtime image), Svelte 5 + TypeScript + Vite + Bun, openapi-typescript/openapi-fetch, Playwright,
Python worker (yue2 on 3.12, ACE-Step on 3.11; runpod SDK, uv, pytest), GitHub Actions, GHCR.

## Execution model

- Each milestone: detailed plan → lanes (backend / web / infra / worker) built by coding agents in
  separate git worktrees → review (spec + quality + security) → fix loop → merge → `make check` +
  `make e2e` green → PR → GitHub CI green → merge to `main` → deploy.
- Every acceptance criterion below becomes a named test (`TestAcceptance_*` in Go or a Playwright
  spec), except items in `docs/device-checklist.md` (real-phone checks CI cannot emulate).
- Coverage gates (from M1): ≥85% statements in `internal/`, ≥95% in `auth`, `spend`, `jobs`,
  `media` range handling.

## Signature features (what makes it new)

1. **One Studio, Three Faces** — REST, MCP and SPA from one registry; CI proves parity, including
   that the SPA actually calls every op that has a UI route (served-operation coverage).
2. **Spend protocol → Spending Mandates** — estimate → single-use confirmation token → worst-case
   reservation in an append-only ledger; human approval above limits; later 2FA-signed mandates.
3. **Ears Dossier** — per-take machine-listening data (loudness, true peak, bandwidth, clipping,
   silence, token loops, spectrogram image, later Whisper diction) with explicit `blind_spots`.
4. **Blind Duel Engine** — loudness-matched, sample-synced blind A/B clips feeding a personal
   Bradley-Terry-Davidson ladder.
5. **Operator Ledger** — every lineage edge is a typed, replayable mutation with rationale.
6. **Song Pull Requests + Callback Listening** — timestamped critique → bounded edit → render →
   "fixed / not yet / worse?" at the same musical spot.
7. **Composer's Desk** — draft cheap ABC plans for many seeds, audition, render only winners.
8. **Italian Diction Lab** — word-level intelligibility karaoke and a personal list of mangled words.

## Milestones

### M0 — Skeleton, privacy-first public repo, CI
Registry + error model + `ping`/`whoami`/`get_system_info`; auth modes (proxy|local) with
path-class trust; personal access tokens (CLI-minted); MCP adapter (tools + generic
`describe_operation`/`call_operation`) with REST↔MCP parity test and `tools/list` golden; Svelte
shell with generated client + fetch ban + served-operation coverage; Makefile + metrics wrapper;
privacy gate (hooks + CI, gitleaks); Dockerfile; CI workflow; MIT licence.
**Acceptance:** CI < 6 min warm; `make check` < 30 s warm; parity + golden tests run; hooks block a
planted `*.pdf` and a planted `mmp_` token; push protection enabled before the first push.

### M1 — Import & listen (spec phase 0 + player)
`import --dry-run` inventory → import (`songs.jsonl` raw bytes kept, audio, per-song JSON, YuE2
result dirs, `varianti/` → drafts, inferred sibling edges, scores attached); ingest freezes masters
(tags once, 0444, sha256 address), MP3 320 rendition, peaks, loudness/bandwidth via ffmpeg Analyzer;
library (FTS5 search + filters), track detail, persistent player with canvas waveform, signed media
URLs with Range; PWA shell (public manifest/icons, Media Session, session-loss reload, device probe);
synthetic seed library for E2E; deploy.
**Acceptance:** [S] all songs imported with lyrics/style/seed/duration/audio; [S] play + seek on
desktop (Chrome + Firefox CI) and phone (checklist); frozen-master invariants; Range matrix;
routing/auth trust matrix; loudness spread reported.

### M2a — Judge, edit, agent parity (spec phase 1)
Human stars + status (agent ratings stored separately as "critic"), tags, general + timestamped
comments (click jumps), draft editor with `lint_recipe`, JSONL batch upload to drafts, playlists +
ZIP export, `songs.jsonl` export (byte-identical for imported rows), backup/restore, `/context`
bundle, audit log, rate limits, idempotency (derived keys over MCP), `/human/` token + device
pages, `mcp-stdio`, listen-event logging.
**Acceptance:** [S] timestamp comment jumps player; [S] rating/status/tag filters; [S] export
byte-identical + `yue2 batch` validator mirror; [S] v2 drafts visible/editable/lint-clean;
[S] backup restore on empty dir; an MCP client with a token performs every M2a UI action;
agent `rate_track` never changes the human rating; `TestNoSecretLeak`.

### M2b — Duels, ladder, Ears Tier A
Blind duels (clips, loudness match, sync A/B), BTD ladder, spectrogram with section overlays,
silence/clipping/token-loop flags, `compare_tracks`.
**Acceptance:** BT parameter recovery on simulated voters; critic verdicts excluded from ladder;
spectrogram ≤ 100 KB.
**Release 1 path:** M2b is on the Release 1 path (D-M3-1): the generation UI's A/B-with-parent duel and
the lineage views of M3 are built on its duels and ladder.

### M2c — Reference tracks and lossy masters
Reference tracks imported with stub recipes (`engine='unknown'`) and lossy (MP3) masters:
`library.RecipeKnown`/`RequireRecipeKnown`/`LosslessMaster` guard every generation mother
(`RECIPE_UNKNOWN`, `LOSSY_MASTER`); `songs.jsonl` export skips stubs; `/context` reports
`recipe.known`; fixtures `librarytest.FixtureM2c`, archive profile `reference`, CI tiers `go-fast`/`go-media`.
**Acceptance:** stub recipes and lossy masters are listened to, rated and judged like any track and are
refused as mothers of generation.

### M3 — Generate (spec phase 2)
Python worker + image (CI-built, contract-tested against pinned yue2 with CPU torch), `runpod probe|
provision|status|canary`, serverless backend + fake backend, estimate/create generation (+ per-track
variant wrappers, `compose_new`), worst-case reservation + residual settlement, caps, approvals via
push + `/human/confirm`, runner with DB lease, resubmit-on-TTL, reconciler with trip/fallback,
Operator Ledger, jobs & costs view, lineage tree + parent A/B, env fingerprints.
**Acceptance:** [S] new-seed variant creates linked child with cost; [S] v2 batch from UI in one
estimate + one confirmation; [S] "new song" root with cost; [S] interruption leaves no GPU running
(user terminate / worker killed / server restart); [S] agent flow search ≥4★ → context → estimate →
create → wait → comment → audit; [S] over budget ⇒ `BUDGET_EXCEEDED`, zero backend calls;
spend property `settled + reserved ≤ cap` at every instant (synctest).

**Release 1 gate:** every [S] item in M1, M2a, M3 green as a named test + device checklist.

### L1 — Library provenance (Muses, Songs, Picks, Sessions, Sounds)
Derived, idempotent library model on top of M0-M3 (plan `docs/plans/2026-10-15-l1-library-provenance.md`): Muses
(reference inspirations), Songs (one per root lineage or draft), Picks (the current best take per Song, with events and
pins), Sessions (import runs, collections, batches), Sounds (a versioned taxonomy of style terms with facets and an
optional tempo measurement), the Muse Board and the reconciler that keeps them consistent (`library reconcile|verify`).
Migration `0008_provenance`. No L1 operation spends money.
**Acceptance:** `library verify` clean on every fixture; the provenance property test; Muse-visibility tests; REST = MCP
parity for every L1 operation; Playwright specs for the Board, Song, Sounds and Muse pages.

### L2 — Library curation (Records, Crates, tapes) — done
Curation on top of L1 (plan `docs/plans/2026-10-28-l2-library-curation.md`; migration `0010_curation`): Records (ordered
slots that follow Picks or are pinned, an append-only changelog, cover, liner notes, energy curve, a human-only publish gate),
Crates (manual and smart), tapes (a gapless, loudness-matched FLAC of a published Record with chapters), the Record
albums and neutral-named auto-albums of the Subsonic server, and two human-only Muse-name opt-ins (both off by default).
No L2 operation spends money.
**Acceptance:** a Pick change upgrades floating slots and logs it; pinned slots never change; tape export verified
(chapters, loudness, gapless, lossy label); Crates and smart Crates; Record albums visible to a Subsonic client; REST = MCP
parity for every L2 operation; `library verify` clean. Open device checks: DC-L2-1, DC-L2-2.

### L3 — Library: agents and Atlas (features, sequencing, next actions, taxonomy proposals, Atlas) — done
Agent-facing and visual layers on top of L1 and L2 (plan `docs/plans/2026-11-02-l3-library-agents-atlas.md`; migration
`0011_agents_atlas`): derived per-take and per-Song features (tempo, key, energy, each with a basis: measured, declared,
plan or predicted), the Record sequencer (`suggest_sequence` and the `sequence` slot operation, with an explanation),
Muse-aware next actions (`list_next_actions`), taxonomy proposals (agents propose, a human decides), the Atlas (a
Song map by tempo, energy, family, vocal and more, with an honest totals and basis layer) and adherence (requested
versus got). Key and energy are measured by two new Tier A analyzers. The M6 "Song Atlas" track is absorbed here
(D-L3-27): the requested-versus-got layer, `get_adherence` and the `/atlas` route are delivered by L3, and M6 no longer
lists them. No L3 operation spends money.
**Acceptance:** an agent builds and proposes a sequenced Record from strong Picks and a human publishes; next actions
that know the Muses; taxonomy proposals with human approval; the Atlas renders the library; `library verify` clean;
REST = MCP parity for every L3 operation. Open device checks: DC-L3-1, DC-L3-2, DC-L3-3.

**Numbering:** L1, L2 and L3 (provenance, curation, agents/atlas) sit between M3 and M4a (L3 took migration `0011`; M5 and M6 renumber after it). M4a took migration `0009` and merged
after L1; L2 took `0010`; L3 and M5/M6 renumber contracts and migrations after whatever merged before them.
Order as built: ... L3 (`0011`), token expiry (`0012`), M5 (`0013`), T1 (`0014`), E2 (`0015`, `0016`); the roadmap order is L3 -> E2 -> T1
-> M4a/M5/M6, and migration numbers follow merge order, not roadmap order.

### E2 — ACE-Step 1.5 as engine #2 (E2a + E2b built; E2c not built)
A second generation engine behind the engine layer (plan `docs/plans/2026-11-06-e2-acestep.md`; migrations `0015_engines`
and `0016_billing_backend`): an engine seam and registry (`list_engines`), a second serverless endpoint and worker image with
its own backend, state, trips and billing, adoption by the operator CLI before an engine may spend, and the ACE-Step modes
`text2music`, `port`, `repaint`, `reference` (turbo class) and `extend`, `complete`, `stems` plus synced lyrics (base class,
off until the canary proves them). Engine trials and Suites (E2c) are not built. Spend is per backend and bounded globally;
the second endpoint is provisioned inactive. This item replaces the ACE-Step track that M5 and M6 used to carry.
**Acceptance:** yue2 jobs and goldens unchanged; an adopted engine's takes ingest, appear in lineage with an engine badge and
cross-engine marks; per-backend isolation (a trip on one backend never touches the other); `settled + reserved <= cap` with two
backends; REST = MCP parity; the canary is the only gate for capability flags. Open device checks: touch range selection,
stem players and the LRC list at 360 px.

### T1 — Transforms (T1a + T1h built; T1b deferred)
Deterministic, ML-free DSP transforms of existing Takes into new Takes (plan `docs/plans/2026-11-06-t1-transforms.md`; migration
`0014_transforms`): `morph`, `shepard`, `glacier`, `polytempo`, `ensemble` and the hi-fi kinds `master`, `widen` and `binaural`
(headphones only), rendered in a child process on the application host with a queue, CPU quotas and a determinism contract
(`GOAMD64=v1`, `transform verify`). Seven generic operations, no dedicated MCP tool. **Transforms never spend money**; the
score renderer (`score_render`, soundfonts) is T1b and is deferred.
**Acceptance:** a transform is an ordinary Take (Songs, Picks, duels, stars) with lineage back to its parents and the parent
never modified; the same spec re-renders to the same hash; every output passes the loudness and true-peak safety stage;
REST = MCP parity. Open device checks: DC-T1-1 to DC-T1-4.

### M4a — Remote agents & native mobile
OAuth for hosted MCP clients via the SSO provider's OIDC (pre-registered clients, JWT verification
via JWKS, per-subject budgets); OpenSubsonic bridge (XML+JSON, raw FLAC stream with Range, star/
rating/scrobble/bookmarks, playlists, lyrics); offline PWA (chunked Cache API, persist); cover art;
MCP resources + prompts.
**Acceptance:** hosted connector completes OAuth and runs `search_tracks` + `add_comment`; native
Subsonic client plays raw 24/48 FLAC with seek and syncs rating; offline set plays offline.

### M4b — (conditional) in-app OAuth authorization server
Only if a required client cannot use pre-registration (CIMD first, DCR fallback, PKCE S256).

### M5 — Close the loop (spend-free core shipped; M5b and M6 deferrals)
Plan `docs/plans/2026-11-06-m5-close-the-loop.md`; migration `0013_close_loop`. Shipped: Song PRs (bounded lyric and style patches
that address comments, rendered through the M3 estimate), Callback Listening ("fixed / not yet / worse?" at the same musical spot),
attention heat strip and hotspots, section-locked duels with pair suggestions, walkie-talkie voice notes, and Receipts (a web
grouping). No M5 operation spends by itself; pacing guards limit agent re-rendering.
**Acceptance:** comment -> patch -> render -> callback verdict resolves the comment (fake engine). Open device checks: DC-M5-1,
DC-M5-2, the voice recorder on iOS.
**Deferred to M5b (separate GPU plan):** Composer's Desk (plan -> audition -> render-from-plan) with the ABC toolkit, Ears Tier B on
GPU (Demucs + faster-whisper diction, SheetSage2 adherence, measured sections) and the Recover recipe. **Deferred to M6:**
Spending Mandates (with Night Shift), the upgrade gate (its seed is E2's engine adoption) and MCP widgets.
